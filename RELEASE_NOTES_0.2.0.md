# PereHomeLab v0.2.0

Личные уведомления Telegram, обновлённые карточки сотрудников и усиление безопасности. Ответственный и комментарии синхронизируются между группой, личными сообщениями и мониторингом. Существующие история, локации, сотрудники и настройки сохраняются.

## Главное

- Подтверждённые сотрудники могут подписываться на личные уведомления отдельно у каждого бота локации.
- В ЛС доступны «Я иду», «Отменить» и «Добавить комментарий». Действия обновляют общий вызов и уже отправленные сообщения, без новых уведомлений при отмене.
- Раздел «Сотрудники» стал компактным списком с поиском и фильтрами. Профиль, подписки и история действий открываются в карточке сотрудника.
- Docker работает без root, от UID/GID `10001:10001`. При обновлении требуется подготовить права существующих каталогов.

## Telegram и личные подписки

- Сотрудник открывает личный чат с ботом нужной локации и отправляет `/start`. Администратор подтверждает профиль существующей галочкой «Запретить изменение и удаление данных в боте».
- После подтверждения в личном меню доступны подписка и отписка. Администратор также может управлять подпиской из карточки сотрудника, если сотрудник уже открыл личный чат с ботом.
- Только подтверждённые сотрудники с доступом к локации могут подписываться и выполнять действия в ЛС. Правила действий в общей группе не изменяются.
- Подписка не рассылает прежнюю историю. Отписка не снимает назначение сотрудника с уже принятого вызова.
- Снятие подтверждения, блокировка или отключение доступа к локации выключают подписку. После восстановления прав подписку нужно включить заново.
- Принятие, смена ответственного, отмена и комментарии общие для группы, ЛС и веб-мониторинга. В ЛС после запроса комментария можно отправить обычный текст; временные запросы очищаются.
- Блокировка бота одним получателем не мешает остальным. Доставка выполняется ограниченными партиями, учитывает временные ошибки и ограничения Telegram. Если результат отправки неизвестен, слепого повтора нет, чтобы не создавать дубли.
- Повторное включение подписки во время временного сбоя отправки не приводит к рассылке вызовов, появившихся до новой подписки.

## Сотрудники и админка

- Список сотрудников поддерживает поиск и фильтры по подтверждению профиля и подписке на ЛС.
- Карточка сотрудника объединяет профиль, доступные подписки по локациям и историю действий с фильтрами и страницами.
- Администраторы локаций могут исправлять ФИО, корпоративный логин и запрет самостоятельного изменения/удаления профиля сотрудников своих локаций.
- Профиль общий для всех локаций сотрудника. Telegram ID, глобальную блокировку и общие ограничения доступа по-прежнему меняют только главный и общие администраторы.
- Подписки и история действий ограничены правами администратора. Локационные администраторы не получают доступ к действиям в чужих локациях.
- Несохранённые правки защищены от автоматического обновления списка; состояния сохранения и ошибки отображаются в карточке.

## Безопасность

- Обновлена библиотека cryptography до 50.0.2. Существующие ключи Fernet и зашифрованные токены совместимы.
- Усилено скрытие токенов, паролей и данных авторизации в логах, трассировках и ошибках интеграций. Просмотр прежних логов через админку также скрывает распознаваемые секреты.
- Процесс контейнера запускается от непривилегированного пользователя; исходный код недоступен ему на запись.
- Версия системного пакета часовых поясов закреплена в Dockerfile.

## Docker

Образы: `bedmah/perehomelab:0.2.0` и `bedmah/perehomelab:latest`.

В отдельной папке развёртывания с заполненным `secret.env`:

```bash
mkdir -p data logs sound app
docker pull bedmah/perehomelab:0.2.0

# Одноразовая подготовка прав каталогов, включая обновление со старых версий.
docker run --rm --network none --user 0 --entrypoint chown \
  -v "$(pwd)/data:/app/data" \
  -v "$(pwd)/logs:/app/logs" \
  -v "$(pwd)/sound:/app/sound" \
  bedmah/perehomelab:0.2.0 -R --no-dereference 10001:10001 /app/data /app/logs /app/sound

docker run -d \
  --name perehomelab \
  --restart unless-stopped \
  -p 80:8000 \
  --env-file secret.env \
  -e HISTORY_DB_PATH=/app/data/press_history.db \
  -e APP_DOWNLOAD_DIR=/download-app \
  --add-host host.docker.internal:host-gateway \
  -v "$(pwd)/data:/app/data" \
  -v "$(pwd)/logs:/app/logs" \
  -v "$(pwd)/sound:/app/sound" \
  -v "$(pwd)/app:/download-app:ro" \
  bedmah/perehomelab:0.2.0
```

## Важно при обновлении с 0.1.3

- Остановите старый контейнер и сделайте защищённую резервную копию `data`, `sound`, `app` и `secret.env` до миграции. Затем удалите только старый контейнер и выполните команды выше с прежними каталогами.
- **Подготовка прав обязательна:** прежние root-owned каталоги могут быть недоступны UID 10001. Команда `chown` не удаляет данные и используется только для подготовки, не для постоянного запуска приложения от root.
- Старый ENV подходит, новых обязательных параметров нет. Если указан `APP_VERSION`, замените его на `0.2.0` или уберите строку, чтобы использовалась версия образа.
- Базу удалять не нужно: таблицы добавляются автоматически. История, сотрудники, блокировки, настройки локаций и токены сохраняются. Для отката используйте резервную копию до миграции.
- Сохраните прежний `TELEGRAM_ENCRYPTION_KEY`, если он задан. Автоматически созданный ключ должен остаться в прежнем каталоге `data`.
- `sound` подключается с записью, без `:ro`. Каталог `app` и EXE должны быть доступны на чтение пользователю 10001; EXE и рабочие звуки не входят в образ.
- Не запускайте два экземпляра с одними Telegram-ботами. Для тестового стенда используйте отдельных ботов или `TELEGRAM_ENABLED=false`.
- Выполните Ctrl+F5. Для админки используйте HTTPS. Windows kiosk-приложение в этом релизе не пересобиралось.
- После обновления проверьте физическое нажатие, звук, принятие в группе и личную подписку тестового сотрудника. Доставка зависит также от связи с HA, Telegram и прав бота.
