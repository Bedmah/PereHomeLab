# PereHomeLab

Веб-мониторинг кнопок переговорок через Home Assistant.

Текущая версия - **0.2.1**: удобнее карточки сотрудников и меню Telegram. [Описание релиза](RELEASE_NOTES_0.2.1.md). Образ работает от UID/GID 10001: при обновлении со старых root-образов нужна одноразовая подготовка прав по [DOCKER.md](DOCKER.md). Прежние ENV, БД, ключи и токены сохраняются.

- Docker Hub: https://hub.docker.com/r/bedmah/perehomelab
- GitHub: https://github.com/Bedmah/PereHomeLab

PereHomeLab подключается к Home Assistant, отслеживает кнопки переговорок, показывает нажатия в веб-интерфейсе, проигрывает звуковые уведомления, сохраняет историю, отображает заряд батарей и позволяет управлять локациями через админку.

## Администраторы

С версии 0.2.0 раздел «Сотрудники» открывается компактным списком с поиском и фильтрами подтверждения/подписки. Нажмите на сотрудника, чтобы открыть профиль, настройки подписок по локациям и историю действий с фильтрами и страницами по 10 записей. Кнопка возврата находится над карточкой; данные и доступ сгруппированы отдельно. Локационные администраторы видят только свои локации; общие изменения профиля явно отделены от настроек бота.

### Личные уведомления Telegram (0.2.0)

- Сотрудник открывает личный чат нужного бота и отправляет `/start`. После подтверждения администратором доступны «Подписаться на уведомления» и «Отписаться от уведомлений»; подписка отдельная у каждого бота/локации.
- Подтверждение соответствует существующей галочке «Запретить изменение и удаление данных в боте». Неподтверждённые и заблокированные сотрудники не могут подписываться или выполнять действия в ЛС. Правила действий в группе сохраняются.
- Новые вызовы приходят с кнопками принятия, отмены и комментария. Ответственный и комментарии общие для группы, ЛС и мониторинга; существующие сообщения редактируются, а не дублируются.
- История после подписки не рассылается. Снятие подтверждения/доступа отключает подписку; восстановление доступа не включает её автоматически. Отписка не отменяет принятую заявку.
- В админке подписка доступна только после открытия ЛС сотрудником. Если получатель заблокировал бота, доставка ему отключается, не мешая группе и остальным. Повторы ограничены; при неопределённом результате отправка не повторяется вслепую.
- Подписки, очередь и история сохраняются в существующем `data`. Новых ENV-параметров нет. Для тестового стенда отключайте Telegram или используйте отдельных ботов.

В меню Telegram отображаются локация и статус профиля: «Не заполнен», «Ожидает подтверждения», «Подтверждён» или «Доступ ограничен». Кнопка подписки показывает текущее состояние и доступное действие. «Отмена» в нижнем меню появляется только во время заполнения или изменения профиля; отмена назначения под вызовом сохранена.

### Настройки и права

Вход: `/admin`. В боковом меню выберите локацию, затем настройки, Telegram или сотрудников. Библиотека звуков доступна отдельно.

В **Общие настройки → Поддержка** главный или общий администратор задаёт одну ссылку для главной страницы, всех мониторов, админки и страницы входа. Разрешены HTTP/HTTPS-ссылки; пустое поле скрывает кнопку. Ссылка хранится в БД в `data`, менять ENV не нужно. Иконки действий имеют текстовые подсказки и названия для экранных дикторов.

ФИО, корпоративный логин и запрет изменения/удаления профиля в боте доступны прямо в карточке сотрудника. С версии 0.2.0 администраторы локаций тоже меняют эти поля у сотрудников своих локаций. Профиль общий: изменения видны во всех локациях, где работает сотрудник. Telegram ID, глобальную блокировку и общие ограничения доступа изменяют только главный и общие администраторы.

Вход выполняется через форму, без браузерного окна Basic Auth. Сессия действует 12 часов; кнопка «Выйти» завершает её на сервере. Блокировка и смена пароля отзывают сессии, новые роли и локации проверяются при каждом запросе. Для продакшена используйте HTTPS. Старые запросы API с явным Basic Authorization остаются совместимыми.

Раздел «Журнал» показывает автора, локацию и изменения «было → стало». Есть поиск, фильтры по локации, разделу, автору и датам, а также страницы. Главный и общий администраторы видят весь журнал, локационный - только записи своих локаций. Пароли и токены не сохраняются в журнале. Старые записи помечены отдельно: восстановить прошлые значения, которые раньше не записывались, невозможно.

- **Главный администратор** задаётся `ADMIN_USERNAME` и `ADMIN_PASSWORD` в `secret.env`. Полный доступ, создание общих и локационных администраторов, смена их ролей и паролей. Главную учётку нельзя изменить или удалить через сайт.
- **Общий администратор** управляет всеми локациями, звуками и сотрудниками. Может создавать, блокировать, удалять локационных администраторов и назначать им локации, но не управляет другими общими администраторами и не повышает роли.
- **Администратор локаций** видит только назначенные локации: звук, повтор, историю, подтверждение и Telegram. Может загружать новые звуки, запрещать/разрешать сотрудникам действия в своём боте, редактировать их ФИО и корпоративный логин, запрещать самостоятельное изменение/удаление профиля. Не может менять Telegram ID, глобальные блокировки и доступ к чужим локациям.

Назначить можно несколько локаций. Ограничения проверяются на сервере при каждом запросе. Старые администраторы сохраняют общий доступ; новые по умолчанию локационные. Изменения структуры БД выполняются автоматически, удалять БД не нужно. Роли, доступы сотрудников и журнал действий хранятся в `data`.

Используемые звуки защищены от удаления, загрузка не перезаписывает существующие файлы. Настройка публичного мониторинга и работа Telegram от смены админского интерфейса не меняются.

## Telegram в версии 0.1.1

1. Создайте отдельного бота для каждого локации через `@BotFather` → `/newbot`.
2. Один раз сгенерируйте ключ шифрования:

   ```bash
   .venv/bin/python -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'
   ```

3. Добавьте в `secret.env` и перезапустите приложение:

   ```env
   TELEGRAM_ENABLED=true
   TELEGRAM_ENCRYPTION_KEY=your_generated_fernet_key
   TELEGRAM_EVENT_TTL_SECONDS=300
   APP_VERSION=0.2.1
   ```

4. Откройте `/admin` → **Telegram**. В карточке локации укажите токен, включите отправку и сохраните.
5. Добавьте бота в нужную группу. Разрешите отправку сообщений. Делать бота администратором или отключать privacy mode не требуется.
6. Администратор группы должен от своего личного аккаунта отправить `/setup@username_бота` в нужной теме. Анонимная отправка от имени группы не подходит.
7. В карточке локации нажмите **Обновить привязку**, затем **Привязать эту тему**. Предложение действует 15 минут.
8. Нажмите **Отправить тест** и проверьте кнопку **Я иду**. Тест не добавляет нажатий в историю.

После подтверждения темы приём `/setup` закрывается: повторные команды не меняют привязку и не вызывают ответы бота. Для переноса в другую тему нажмите **Изменить привязку** в админке. Это открывает новое окно регистрации на 15 минут. Если окно первичной настройки истекло, используйте **Начать привязку**. Одинаковые команды не заменяют предложение привязки, кнопки подтверждения обрабатываются с приоритетом, а ошибка отдельного сообщения не останавливает очередь.

Токены хранятся в SQLite в зашифрованном виде и не возвращаются в браузер. Ключ хранится только в `secret.env` / переменных окружения. Сохраняйте **и `data`, и прежний ключ**: при потере ключа токены потребуется ввести заново.

Нажатия получает сервер через long polling; публичный адрес и дополнительные порты не нужны. Один бот должен обслуживаться только одним запущенным экземпляром приложения. Для тестового стенда используйте других ботов или отключите интеграцию через `TELEGRAM_ENABLED=false`. Уже используемый webhook приложение не удаляет. После изменения обработчика команд может потребоваться до 15 секунд; при конфликте двух обработчиков остановите второй и сохраните настройки локации заново.

Каждое живое нажатие создаёт отдельное сообщение в выбранной группе и теме. Первый сотрудник, нажавший **Я иду**, принимает вызов. Соответствующее звуковое оповещение закрывается в открытых веб-мониторах. **Кнопка подтверждения в вебе только отключает звук, но не назначает сотрудника.** Другие вызовы остаются активными.

В одном сообщении всегда доступны три кнопки: **Я иду**, **Отменить**, **Добавить комментарий**. «Я иду» другого сотрудника сразу меняет ответственного без подтверждения. Повторное нажатие тем же сотрудником не создаёт новых действий. Отмена освобождает вызов без повторного окна и звука в веб-мониторах. Кнопки общие для всех участников; по умолчанию смена ответственного доступна каждому. Администратор может ограничить отмену и замену текущим ответственным. Одновременные действия применяются последовательно, повтор одного callback не выполняет действие заново.

В карточке истории под временем отображается «Пошёл»: корпоративный логин, а если его нет - Telegram username. В деталях видны ФИО, корпоративный логин и Telegram; для незаполненного профиля показывается только Telegram. Если username отсутствует, используется имя Telegram или ID.

Минимальный антиспам Telegram: до 12 быстрых действий с восстановлением лимита за 10 секунд на сотрудника и бота, отдельно для сообщений и кнопок. Избыточные действия не меняют базу; предупреждение при нажатиях выдаётся не чаще одного раза в 5 секунд. Лимит одного сотрудника не мешает другим. Это не защита от распределённой атаки; для публичного размещения нужны HTTPS и ограничения на reverse proxy.

Комментарии необязательны. Кнопка создаёт временный запрос и автоматически открывает режим ответа Telegram (ForceReply). Ответьте текстом в течение 15 минут; можно ответить и на исходное уведомление, если предварительно нажали кнопку комментария. В группе нужен привязанный ответ; в ЛС после нажатия кнопки комментария можно отправить обычное текстовое сообщение. Ввод привязан к инициатору; `/cancel` отменяет ввод. Повторное нажатие кнопки заменяет прежний запрос. После сохранения запрос удаляется, ответ сотрудника тоже удаляется при наличии прав; неиспользованный запрос очищается через 15 минут. Для удаления ответов сотрудников в супергруппе нужны права администратора с разрешением удаления сообщений. Без этих прав комментарий сохраняется, но ответ остаётся в чате, а причина записывается в лог. Сетевые сбои очистки не блокируют доставку уведомлений. Комментарии доступны в деталях нажатия, а технический журнал действий сохраняется только в SQLite; последние три комментария появляются в исходном уведомлении Telegram. Статуса «Готово» нет.

Для регистрации сотрудник отправляет **/sync** и переходит в личный чат бота. После ввода корпоративного логина, ФИО и подтверждения профиль активируется сразу, без одобрения администратора. **Логин вводится самостоятельно, это не проверка AD и не подтверждение личности.** Профиль общий для всех региональных ботов. В `/admin` → **Сотрудники** доступны поиск, исправление данных, блокировка, ограничение локаций, отвязка Telegram ID и журнал изменений. Сотрудник не получает доступ в админку. В карточке Telegram локации можно включить обязательный профиль для действий.

В истории есть поиск по кнопке, сотруднику и комментарию, фильтры статуса и дат. Время нажатий и действий отображается в формате `дд.мм.гггг чч:мм:сс`; технические даты в БД остаются ISO. База обновляется автоматически, удалять её не нужно. Перед обновлением сохраняйте резервную копию `data` и ключ шифрования.

Исторические нажатия, загруженные из HA, в Telegram не рассылаются. Очередь новых сообщений сохраняется в БД и повторяет временно неудавшиеся запросы в пределах `TELEGRAM_EVENT_TTL_SECONDS` (по умолчанию 5 минут). Если Telegram мог принять сообщение, но ответ потерялся, состояние показывается как **доставка не подтверждена**: автоматического повтора нет, чтобы не создавать дубли. Нажатие кнопки на таком доставленном сообщении всё равно принимается. Статистика и ошибки видны в карточке локации. Telegram не блокирует получение событий HA.

Настройки и токены Telegram сохраняются в volume `data`. Ключ передаётся через `--env-file secret.env`, внутрь образа его добавлять не нужно. Сборка: `docker build -t perehomelab:0.2.1 .`.

## Быстрый запуск версии 0.2.1 в Docker

Перед запуском подготовьте права `data`, `logs` и `sound` по [DOCKER.md](DOCKER.md). Старые root-owned каталоги недоступны новому непривилегированному процессу.

```bash
mkdir -p /docker/perehomelab
cd /docker/perehomelab
mkdir -p data logs sound app
```

Создайте `secret.env`:

```env
HA_URL=http://host.docker.internal:8123
HA_TOKEN=your_home_assistant_long_lived_token

HA_AUTO_DISCOVER=true
HA_ENTITY_IDS=
HA_ENTITY_DOMAIN=binary_sensor
HA_DEVICE_CLASS=safety
HA_ENTITY_ID_SUFFIX=
HA_TRIGGER_FROM=
HA_TRIGGER_TO=on
HA_RECONNECT_SECONDS=5
HA_REFRESH_ENTITIES_ON_RECONNECT=false
HA_SYNC_HISTORY_HOURS=24
HA_HISTORY_RECONCILE_SECONDS=300
HA_HISTORY_OVERLAP_SECONDS=30
HA_HEALTHCHECK_SECONDS=30
HA_ENTITY_REFRESH_SECONDS=900

BUTTON_SOUND=sound/1.mp3
SOUND_PLAY_SECONDS=25
ACK_BUTTON_TEXT=ФА
HISTORY_DB_PATH=data/press_history.db
HISTORY_DEDUP_SECONDS=3

ADMIN_USERNAME=your_admin_login
ADMIN_PASSWORD=replace_with_a_strong_password

APP_DOWNLOAD_DIR=/download-app
APP_DOWNLOAD_FILENAME=PereHomeLabKiosk.exe
APP_VERSION=0.2.1
```

Запустите контейнер:

```bash
docker run -d \
  --name perehomelab \
  --restart unless-stopped \
  -p 80:8000 \
  --env-file secret.env \
  --add-host host.docker.internal:host-gateway \
  -v "$(pwd)/data:/app/data" \
  -v "$(pwd)/logs:/app/logs" \
  -v "$(pwd)/app:/download-app" \
  -v "$(pwd)/sound:/app/sound" \
  bedmah/perehomelab:0.2.1
```

Откройте веб-интерфейс:

```text
http://SERVER_IP/
```

Админка:

```text
http://SERVER_IP/admin
```

## Home Assistant

`HA_URL` - адрес Home Assistant.

Примеры:

```env
HA_URL=http://host.docker.internal:8123
HA_URL=http://192.168.1.50:8123
HA_URL=http://homeassistant:8123
```

`HA_TOKEN` - долгоживущий токен Home Assistant.

PereHomeLab проверяет доступность HA каждые 30 секунд, автоматически
сверяет пропущенную историю каждые 5 минут и после каждого переподключения.
Список сущностей и пространств обновляется каждые 15 минут.

После изменения `secret.env` контейнер нужно пересоздать, потому что `docker restart` не перечитывает `--env-file`.

## Локации

Локации настраиваются в `/admin`.

Для каждой локации можно указать:

- название локации;
- slug для короткой ссылки;
- пространство Home Assistant;
- звук уведомления;
- текст кнопки подтверждения;
- длительность или количество повторов звука;
- сколько часов истории подтягивать.

## Проверка

В деталях нажатия мониторинг показывает «Пошёл», имя текущего ответственного, платформу и дату его принятия в формате `дд.мм.гггг чч:мм:сс`, а ниже - комментарии с автором и временем. При смене ответственного данные обновляются в открытом окне; после отмены отображается «Ожидает сотрудника». Полный журнал принятия, смены ответственного и отключения звука остаётся в БД, но не выводится в этом окне.

### Сотрудники

В личном чате `/start` открывает постоянное меню: просмотр данных, заполнение или изменение профиля и очистка корпоративного логина/ФИО. Очистка не удаляет историю вызовов, Telegram-контакт и ограничения доступа. Для ввода используются отдельные шаги и подтверждение; «Отмена» завершает ввод.

В карточке сотрудника администратор может включить «Запретить изменение и удаление данных в боте». Сотрудник по-прежнему может работать с вызовами, но его профиль изменяет только администратор. Ограничение действует во всех региональных ботах, включая уже открытые подтверждения.

В `/admin` → **Сотрудники** → **Добавить сотрудника** укажите корпоративный логин и ФИО. Telegram ID необязателен; без него созданная запись ещё не связана с Telegram-аккаунтом.

При сообщении боту в личном чате, полученной команде/ответе в группе или нажатии кнопки пользователь автоматически появляется в списке. До заполнения корпоративных данных видны его Telegram-имя и ID, а карточка помечена «Нужно заполнить логин и ФИО». Такие записи можно исправлять и блокировать. Автообнаружение не подменяет заполненный профиль и не снимает блокировку. Если локация требует профиль, автоматически найденный участник должен сначала заполнить логин и ФИО через `/sync` или с помощью администратора.

Записи общие для всех региональных ботов. Доступных из локальной истории участников сервис переносит в список один раз. Список обновляется примерно каждые 10 секунд, пока вкладка открыта; несохранённые правки не перезаписываются. Для пользователя, уже появившегося автоматически, заполняйте его существующую карточку: одинаковые логины и Telegram ID не дублируются и не связываются автоматически по введённому логину.

Важно: сервис видит только события, которые Telegram передал боту. При включённом privacy mode обычные сообщения в группе могут не поступать; команды боту, ответы на его сообщения и нажатия кнопок поддерживаются без отключения privacy mode. Архив всей переписки и всех участников группы через этот механизм не загружается.

Звук подготавливается автоматически при открытии страницы. Если браузер запрещает автозапуск, статус честно показывает «Разрешить звук»: достаточно нажатия на страницу или эту кнопку, отдельно нажимать «Проверить» не нужно. В kiosk-браузере с разрешённым autoplay взаимодействие не требуется. Настройка громкости сохраняется в браузере. «Проверить» не прерывает уже активное оповещение.

Автоматические проверки:

```bash
python -B -m unittest discover -s tests -q
```

Дополнительная проверка интерфейса требует Playwright в отдельном тестовом окружении и работающего сервера:

```bash
python tests/browser_monitor.py --url http://localhost:8000
```

Для установленного Chromium/Edge можно передать `--browser /path/to/browser`, а для скриншотов - `--output /tmp/monitor-check`. Проверка подменяет проигрывание звука и подтверждения: реальные вызовы и сообщения Telegram не изменяются.

```bash
curl http://localhost/api/status
curl http://localhost/api/diagnostics
curl http://localhost/api/batteries
curl http://localhost/api/history
```
